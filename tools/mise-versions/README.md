# mise-versions

The single writer of the image's frozen tool generation.

`config/mise/image-tools.toml` holds the versions the devcontainer bakes into
`/etc/mise/config.toml`, fetches as verified tarballs, and that `install.sh`
uses on a bare Linux host before mise exists. This command renders those
versions into the two scripts that carry them, and reports drift between the
source and what is committed.

## Usage

```bash
# report drift (the leg `just lint` and `just check` run)
mise exec -- go run tools/mise-versions/main.go check

# regenerate the regions after editing the source
just mise-versions-sync

# another checkout
go run tools/mise-versions/main.go check --root /path/to/dotfiles
```

Without `--root` the checkout is resolved from this file's location, so the
working directory does not matter.

## What it generates

- `.devcontainer/features/dotfiles-tools/install.sh` — the body of the
  `/etc/mise/config.toml` heredoc, plus `UV_VERSION`, `JUST_VERSION` and
  `SHELDON_VERSION`
- `install.sh` — `_mise_ver` and `_just_ver`

Everything else in both files is hand-written.

## What it refuses

The source is the frozen generation of an image, so a version that moves is a
bug: `latest`, `lts`, partial versions (`24`), prefixes (`prefix:24`) and the
empty string are all rejected. Every `[tools]` and `[fetch]` tool must also be
declared in `config/mise/config.toml`, and where the host pins an exact version
the two must agree. Each version belongs in exactly one channel (`[tools]`,
`[fetch]`, `[bootstrap]`). Validation and rendering errors leave both outputs
unchanged; multi-file atomicity on disk write failures is not guaranteed.

## Why Go, and why a hand-rolled TOML reader

ADR 0060 recorded the Python exception; ADR 0061 replaces it and exempts this
repo-local generator from binary distribution. Go has no
standard-library TOML reader and this repo asks for the standard library first,
so only the subset these two files use is parsed — comments, table headers,
bare and quoted keys, basic strings with escapes, inline tables and string
arrays — and anything else is a hard error rather than a silent misread. The
host config is only read through its `[tools]` section, because the rest of
that file carries shapes this tool has no business parsing.

Correctness is checked from two sides: this module's own tests, and
`tests/unit/test_mise_versions.py`, which drives the CLI and reads the result
back with Python's `tomllib`. The port from Python was verified by comparing
the generated bytes on the committed input: the two `install.sh` files were
unchanged before updating their generator-name comments. This fixture check
is not a proof of equivalence on every input.
